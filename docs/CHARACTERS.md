# キャラクター表と口調の確認

機械翻訳では、話者が分からないまま 1 行ずつ訳すと、口調がずれやすい (女性キャラクターが「俺」「〜だぜ」で話す、
丁寧語とタメ口が混ざる など)。gtl はこれを、次の 4 つで防ぐ。

1. **キャラクター表** (`games/<game>/characters.yaml`): 話者ごとの性別・性格・一人称・二人称・話し方・使わない言い方・例文
2. **話者の割り当て**: 翻訳単位の `context.speaker` に話者を入れる (ゲーム固有の拡張が、エンジンから取れる情報で入れる)
3. **翻訳の指示**: `gtl translate -speakers characters.yaml` で、話者のプロフィールを翻訳の文脈としてモデルに渡す。
   表があるのに話者が分からない台詞には「性別が強く出る言い方を避け、中立的な口調で訳す」と指示する
4. **確認**: 訳文が表と合わない行に警告を付ける (翻訳のとき・`gtl recheck`)。手修正済みの行も含めて一覧するのは `gtl speakers-check`。
   既に訳した分を点検するときは `-masculine` で、表に書いていない男言葉 (下の「男言葉の点検」) も拾える

**口調を決めるのはキャラクター表で、性別だけで機械的に決めない。** 乱暴な口調の女性キャラクター、丁寧な口調の男性キャラクターも
いるので、表に書いたとおりに訳し、確かめる。

## キャラクター表の書き方

```yaml
# gender ごとの既定。キャラクター側に書いた項目が優先 (空のリスト [] を書けば既定を使わない)
defaults:
  female:
    avoid: [俺, 僕]                              # 文中のどこでも使わない言い方
    avoid_endings: [だぜ, ぜ, じゃねえ, だな, ぞ]  # 文の終わりで使わない語尾

characters:
  Alice:                       # context.speaker の値
    aliases: [ALIC]            # 同じ人物を指す別の話者名 (表記ゆれ・音声ファイルの略号など)
    gender: female             # female / male / other (分からなければ書かない)
    note: 主人公。皮肉屋で気が強い大学生   # 立場・性格 (モデルへの文脈)
    first_person: 私            # 一人称。表と違う一人称 (俺/僕/あたし) が出たら警告
    second_person: あなた        # 相手の呼び方
    speech: くだけた口調。「〜よ」「〜ね」。男言葉は使わない   # 話し方・語尾
    examples:                  # 口調の例 (訳文の例。2〜3 個)
      - 子どもの頃から会ってない。大昔の話よ。
  Rose:
    gender: female
    note: 荒っぽい運び屋
    first_person: あたし
    speech: 乱暴な口調。「〜だぜ」「〜しな」も使う
    avoid_endings: []          # 既定の「使わない語尾」を外す (この人物は使ってよい)
    allow: [男言葉]             # 男言葉の確認を全部外す
  Sova:
    gender: female
    note: 荒っぽい姐御。「あんた」「〜だろ」は使うが、「俺」「〜ぜ」は使わない
    first_person: あたし
    second_person: あんた
    allow: [〜だろ, 命令形 (〜しろ・〜やれ)]   # この言い方だけ許す (名前は下の表)
```

- **分かっていない項目は書かない。** 推測で書くと、間違いが全部の行に広がる。性別が分からない人物は gender を空にする
- `avoid` は部分一致なので、ほかの語に紛れやすい短い語 (「わし」→「出くわし」など) は入れない。語尾は `avoid_endings` に書く (文の終わりでだけ見る)
- 既定 (`defaults`) はゲームごとに決める。手で直した口調の傾向 (下の「表を育てる」) から足していく

## 男言葉の点検

キャラクター表が無いころに訳した分や、表の `avoid` に書き漏れがある分を点検するための確認。
`gtl speakers-check -masculine` を付けると、gender: female の話者の訳文について、表の `avoid` / `avoid_endings` に加えて
次の男性的な言い方を調べる (`internal/translate/tone.go`)。翻訳の指示や自動の訳し直しには使わない
(新しく訳す分は、キャラクター表と、会話をエージェントが直接訳す流れ ([TRANSLATION.md](TRANSLATION.md)) で防ぐ)。
勝気・乱暴な口調の人物は、許す言い方の名前を `allow` に書く (全部許すなら `allow: [男言葉]`)。
性別だけで決めず、人物ごとに「どこまで許すか」を表で決める。

| 名前 (`allow` に書く) | 拾う例 | 拾わない例 |
|---|---|---|
| `俺` | 俺 (一人称を表に書いた話者は一人称の確認で拾う) | |
| `お前` | お前、てめえ、貴様 | |
| `あいつ` | あいつ、こいつ、そいつ | そこ**いつ**も |
| `野郎・クソ` | 野郎、クソ、くそっ | 約束 (やく**そく**) |
| `〜ぜ・〜ぞ` | 行くぞ！、やるぜ | どうぞ、なぜ、それぞれ |
| `〜だな・〜するな` | 決まりだな、分かってるな？、言うなよ | 〜かな、〜ような、勉強になるなあ |
| `〜か？` | 満足か？、知ったことか。、覚えてるか？ | 満足ですか？、でしょうか、何か？、どれだけうれしいか、なんていうか、まあいいか、どうして〜なのか。 |
| `〜んだ？・〜のか` | どうするんだ？、あるのか？、通じないんだ！ | 会ったんだよ、そうなんだ！ |
| `〜だろ` | 冗談だろ！、言っただろ | 残したんだろう？ (独り言)、選んだだろう。 (推量) |
| `〜かよ` | 本気かよ | |
| `〜ねえ (否定)` | 知らねえ、じゃねえ | いいねえ |
| `〜やがる` | 何しやがる | |
| `命令形 (〜しろ・〜やれ)` | 黙れ！、言ってやれ、出て行け | 何しろ |
| `おい` | おい、待て | |

拾ったら、`gtl speakers-check -masculine -summary` で話者ごと・言い方ごとの件数を見て、多い人物から直す。
誤検知が多い言い方を見つけたら、`tone.go` の除外条件とテスト (`speakers_test.go` の「拾ってはいけない」例) に足す。

## Claude がキャラクター表を作るとき

1. **登場人物を洗い出す**: 抽出した原文の話者 (`context.speaker`) の一覧と出てくる回数、音声ファイルの略号、
   ゲーム内の人物名鑑・会話の名前表示などから。回数の多い人物から書く
2. **人物像を調べる**: 原文の台詞 (話し方、呼ばれ方、"he"/"she" などの代名詞)、ゲームの公式説明・Wiki など公開されている情報から。
   出典が無いことは書かない。ネタバレになる情報は note に書かなくてよい (翻訳に要る範囲で)
3. **一人称・語尾を決める**: 原文の口調 (乱暴・丁寧・子どもっぽい・年配) と性格から。迷う人物は、試験翻訳で 2〜3 通り見せてユーザーに選んでもらう
4. **ユーザーに確認する**: 表の下書きを見せ、直してもらってから全文翻訳に進む。表はユーザーが編集してよいものとして扱う

## 話者の割り当て (ゲーム固有の拡張でやること)

エンジンから取れる情報で `context.speaker` を入れる。取れない台詞は空のままにする (中立的な口調の指示が入る)。

| エンジン・形式 | 話者の手がかり |
|---|---|
| 台詞データに話者の列がある (Unity の台詞表など) | その列をそのまま使う |
| AGS (`.tra` + `speech.vox`) | 台詞の `&N` の番号と、音声ファイル名 (「話者の略号 + 番号」、例 `KATH1390`)。番号が 1 人だけのものなら話者が決まる |
| Unreal Engine (locres) | locres には話者が無い。会話のデータ (DataTable・Dialogue Wave など) のキーと話者の対応を探す |
| Godot (`.translation`) | 翻訳キーの名前 (`npc_alice_03` など) や、会話のリソース (`.dialogue`・`.tres`) の話者 |
| 手がかりが無い | 会話の流れ (前後の行、名前の呼びかけ) から人が割り当てる。量が多ければ割り当てずに、確認 (下) で直す |

話者を後から足したときは、翻訳し直さなくても `gtl recheck -context-from <抽出し直した原文>` で話者を取り直して確かめられる。

## 確かめる・直す

```bash
# 翻訳 (話者のプロフィールを渡す。表と合わない訳は警告が付き、再試行される)
./scripts/gtl.sh translate -in work/<game>/source.jsonl -out games/<game>/ja.jsonl -speakers games/<game>/characters.yaml ...

# 表と合わない行の一覧 (手修正済みの行も含む。ファイルは書き換えない)
./scripts/gtl.sh speakers-check -in games/<game>/ja.jsonl -speakers games/<game>/characters.yaml
# 件数だけ (話者ごと・警告の種類ごと)。-masculine で表に無い男言葉も点検する
./scripts/gtl.sh speakers-check -masculine -summary -in games/<game>/ja.jsonl -speakers games/<game>/characters.yaml

# 機械翻訳の行の警告を付け直して、合わない行だけ訳し直す
./scripts/gtl.sh recheck -in games/<game>/ja.jsonl -speakers games/<game>/characters.yaml
./scripts/gtl.sh translate ... -speakers games/<game>/characters.yaml -retry-warned -attempts 5
```

直した訳は `games/<game>/fixes.tsv` に入れて `gtl review` で取り込む (再翻訳で上書きされない)。

## 表を育てる

人が口調を直したら、直す前の訳に多かった語尾・言い方を表の `avoid` / `avoid_endings` に足す。
次からは機械翻訳の段階で警告が付き、再試行で直るようになる。足したあとは `gtl speakers-check` で、
直した後の訳 (正しい訳) に警告が出ないこと (誤検知が少ないこと) を確かめる。
