# エンジン別の日本語化 (多言語化) の方法

これまで使った方法を、エンジンごとに一般的な形でまとめる (ゲームごとの詳しい調査結果はここには書かない)。新しいゲームを調べるときの出発点にする。
ここに当てはまらないゲームの調べ方は [RESEARCH.md](RESEARCH.md)。
どの方法でも、**ゲームフォルダは読み取りだけで調べ、書き込みは `gtl install` で (ユーザーに確認してから) 行う**。
ゲームのファイルは書き換えずに「足す」方法を優先し、外せば元に戻るようにする。

## まず確かめること

| 確かめること | 見る場所・方法 |
|---|---|
| エンジン | exe と同じ階層のファイル (`UnityPlayer.dll` + `*_Data/` → Unity、`*.pak` + `Engine/` → Unreal、`*.pck` → Godot、`acwin.exe` や exe 末尾の `CLIB` → AGS、`data.win` → GameMaker) |
| 公式の翻訳の仕組み | ゲームが翻訳 Mod・翻訳ファイルの追加に公式に対応していないか (gettext の `.po` など)。対応していれば一番安全 |
| テキストの場所と形式 | 既知の形式か (locres, .translation, .tra, .po, CSV/TSV, JSON)、独自形式か。英文で grep して探す |
| 既存の翻訳 | ゲームの中に使われていない言語のデータが無いか (家庭用版の公式訳が同梱されていることがある)、ファン翻訳の有無とライセンス |
| フォント | 訳文の言語の字が入っているか。入っていなければ差し替えか追加が必要 |
| 言語の枠 | ゲーム内に言語メニューがあるか。下の「言語の枠の選び方」を参照 |

### 言語の枠の選び方

訳文を出すために、ゲームが持っている言語の 1 つを「訳文の枠」として借りることが多い。

- **使っていない言語の枠** (例: 中国語・イタリア語) を借りる: 英語の表示と切り替えられる。その言語向けのフォント (CJK など) や表示時間の設定がそのまま使えることがある
- **英語の枠** を置き換える: ゲームが英語の文字列そのものに頼っている場合 (検索語の照合、画像の切り替え、名前の判定など) に向いている。英語の表示とは切り替えられなくなる
- 言語メニューに出る名前 (「English」など) は、訳文の言語の名前に差し替えておくと分かりやすい

## ゲームが公式に翻訳 Mod に対応している場合

- **向いている場合**: ゲームが翻訳ファイル (gettext の `.po` など) を Mod として読み込める
- **方法**: 公式の形式で翻訳 Mod を作り、ゲームの Mod フォルダ (ユーザーのドキュメントフォルダなど) に置く。ゲームのファイルは触らない
- **手順**:
  1. ゲームに同梱されている原文のテンプレート (`.pot` など) を原文として使う (抽出は不要)
  2. 既存のファン翻訳があれば、ライセンスを確かめて土台にし、足りない分だけ訳して上書きする。足りない行は一覧 (`todo.po` など) に書き出す
  3. 書式記号 (`{0}`、`<link=...>` など) がずれていないかを確かめる (ゲームが検査してエラーにすることがある)
- **注意**: 土台にした訳のライセンス文 (MIT なら著作権表示) を Mod に同梱する

## Unity (Mono) — BepInEx プラグイン

- **向いている場合**: `*_Data/Managed/Assembly-CSharp.dll` がある (IL2CPP でない)。テキストがアセットの中にあって書き換えが大変
- **方法**: [BepInEx 5](https://github.com/BepInEx/BepInEx) + 自作プラグイン (Harmony) で、テキストを返すメソッドの戻り値を差し替える。
  ゲームのファイルは書き換えず、BepInEx のフォルダを消せば元に戻る
- **手順**:
  1. ILSpy などで `Assembly-CSharp.dll` を読み、台詞やメニューの文字列を返すメソッドを探す
  2. 原文はアセット (UnityFS) から抽出する。行の ID を訳文 TSV のキーにする
  3. プラグインは、借りた言語の枠を選んだときだけ訳文を返す。訳の無い行は英語にする
  4. フォントは、OS のフォント (`Font.CreateDynamicFontFromOSFont`、gtl.yaml の `fonts.system`) を訳文の言語の字を含むラベルだけに当てる
  5. 言語メニューの表示 (名前・国旗の画像) も、借りた枠のものを訳文の言語のものに差し替える
  6. 実行中に英語のまま出た文字列をプラグインで記録して、翻訳対象に足す
- **ビルド**: .NET SDK のコンテナでプラグインをビルドし、BepInEx は sha256 を確かめて取得する
- **注意**: IL2CPP のゲームは BepInEx 6 (IL2CPP 版) が必要で、手順が変わる

## Unreal Engine 4 — locres + `_P.pak`

- **向いている場合**: `Content/Localization/<ターゲット>/<言語>/*.locres` がある、pak が暗号化されていない
- **方法**: 訳文を入れた locres と、訳文の言語の字を含むフォントを入れた pak (`pakchunk99-<Platform>_P.pak`) を Paks フォルダに足す。
  `_P` の pak は元の pak より優先して読まれるので、元の pak は変えない。消せば元に戻る
- **手順**:
  1. pak の索引を読み (pak の版ごとに圧縮方式の書き方が違う)、locres を取り出す
  2. locres (v2 は文字列の参照回数あり) を読み、キーごとに翻訳単位にする。`{lb}` などの改行記号は `\n` にして訳し、元の書き方に戻す
  3. 英語しか無いゲームでは、英語 (en) の locres を訳文で置き換える (言語の選択肢は増えない)
  4. フォント: `.ufont` は中身がそのまま TTF/OTF なので、訳文の言語のフォント (gtl.yaml の `fonts.file`) と入れ替えた `.ufont` を同じパスで pak に入れる
- **注意**: 暗号化された pak (AES) は鍵が無いと扱えない。UE5 の IoStore (`.utoc/.ucas`) は別の手順が要る

## Godot 4 — `override.cfg` で言語の枠を差し替え + 追加スクリプト

- **向いている場合**: `.pck` の中に `*.translation` (Godot の翻訳リソース) がある
- **方法**: ゲームの exe と同じ場所に `override.cfg` を置き、`internationalization/locale/translations` の一覧のうち、
  借りる言語の枠のファイルを、ゲームの外のフォルダに置いた訳文の `.translation` に向ける。
  ゲームの動きを足したいとき (日本語の入力を許す、検索語に別名を足す、言語メニューの名前を変えるなど) は、
  同じ `override.cfg` の `[autoload]` で追加の GDScript を読み込む。`override.cfg` と訳文のフォルダを消せば元に戻る
- **手順**:
  1. pck から `.translation` (OptimizedTranslation) を読み、原文を取り出す
  2. BBCode (`[b]` など) は `<n>` `</n>` の番号付きの記号にして訳し、戻す。段落ごとに分けて訳す
  3. 検索語のように「英語のまま入力させる語」は用語集で英語に固定し、必要なら訳文に日本語の読みを併記する
  4. 訳文を同じハッシュ表の形で `.translation` に書き戻す。置き場所は `game.yaml` の `mod_dir` (既定は `install_dir/<言語コード>`)
  5. 追加スクリプトを使う場合は、`override.cfg` に `[autoload]` の行を足し、スクリプトと設定ファイルを訳文と同じフォルダに置く
- **注意**: フォントに訳文の言語の字が無い場合は、テーマのフォントの差し替えも必要。検索などが英語の文字列に頼るゲームは英語の枠を置き換える

## Adventure Game Studio (AGS) — `.tra` 翻訳ファイル + 新しいエンジン

- **向いている場合**: AGS のゲーム。既存の `.tra` (ほかの言語の翻訳) があれば原文の一覧がそのまま手に入る
- **方法**: UTF-8 の `<言語名>.tra` を作る。古いエンジン (3.3 など) は UTF-8 と TTF の差し替えに対応していないので、
  公式の新しい AGS エンジン (3.6 系) を同梱して `acwin.exe --translation <言語名> <ゲーム>.exe` で起動する。ゲームのファイルは書き換えない
- **手順**:
  1. 既存の `.tra` を読み、原文を取り出す (`[` は改行、音声付きの行は `&123 ` の接頭辞を保つ)
  2. 訳文を UTF-8 の `.tra` に書き、`.tra` の中でゲームのフォントを訳文の言語の TTF (ドット絵風なら gtl.yaml の `fonts.bitmap`) に差し替える
  3. 起動用のバッチと Steam の起動オプションの書き方を用意し、エンジン・SDL2・フォントのライセンス文と一緒にまとめる
- **注意**: 画面の解像度が低いゲームは、ドット絵風のフォント (12px 前後) のほうが読みやすい。新しいエンジンは元のゲームのプラグイン (Steam 実績など) を読み込めないことがある

## ゲーム独自のエンジン — 描画をフックする DLL

- **向いている場合**: テキストは書き換えられるが、エンジンが 1 バイト文字しか描けない
- **方法**: ゲームが読み込むシステム DLL (例 `GLU32.dll`) と同じ名前のプロキシ DLL をゲームフォルダに置き、
  本物の関数はそのまま転送しつつ、文字描画の関数をフックして、UTF-8 の文字列を TTF (stb_truetype) で描く。
  テキストのファイルは UTF-8 の訳文に置き換える (上書きする元のファイルは `gtl install` が退避する)
- **手順**:
  1. どの DLL を読み込んでいるか (インポート表) と、文字描画に使っている関数を調べる
  2. プロキシ DLL を MinGW のコンテナでビルドする
  3. フックが 1 つの文字列で描ける字の種類に上限がある場合は、超える行をビルドのときに警告する
  4. 言語メニューの名前など、訳さない行も手修正 (`fixes.tsv`) で差し替えられるようにする
- **注意**: ウイルス対策ソフトに誤検知されることがある。配布するときはソースとビルド手順を一緒に出す

## データに公式訳が同梱されている場合 — 枠の入れ替え

- **向いている場合**: PC 版のデータに家庭用版などの日本語訳とフォントが入っているが、PC 版では選べない
- **方法**: データの「英語」の枠に、同じデータ内の日本語を書き込む (フォント・文字の入った画像も同様)。機械翻訳は不要。
  公式訳の無い PC 版だけの項目は、手で訳して追加する。データのファイルを書き換える代わりに、ゲームが読む追加データ (パッチ・Mod フォルダ) で済むならそちらを使う
- **手順**: データ形式の読み書きを作り、英語の枠を日本語で置き換えたファイルを作る。上書きする元のファイルは `gtl install` が退避する
- **注意**: 公式訳そのものはゲームのデータなので、書き換えたファイルを配布してはいけない。配布するのは「手元のゲームから作る手順とツール」
