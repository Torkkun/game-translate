# これまでの失敗と対策

いくつかのゲームを日本語化して分かった、つまずきやすい点と対策をまとめる。エンジンごとの方法は [ENGINES.md](ENGINES.md)、
口調をそろえる仕組みは [CHARACTERS.md](CHARACTERS.md)、翻訳エンジンの使い分けは [TRANSLATION.md](TRANSLATION.md)。
新しいゲームに取りかかる前と、全文翻訳の後に読み直す。

## 1. 調査: 作る前に「もうあるもの」を探す

| 失敗しかけたこと | 対策 |
|---|---|
| 翻訳を作り始めてから、データの中に家庭用版の公式日本語訳が眠っていると分かる | テキストの表を見つけたら、**まず全部の言語の列を数える**。英語以外の列・使っていない言語の番号・`*_JP` のフォントやスプラッシュ画像を探す。設定ファイルの言語番号を変えるだけで済む場合もある |
| 公式訳はあるがフォントに日本語が無い | 公式訳を英語の枠に入れ、使っている字だけのビットマップフォント (BMFont など) を作る。似たゲームのフォントを流用するときは、**使う字のうち何字が足りないか**を先に数える (3 分の 1 足りないこともある) |
| 既存のファン翻訳を見落として作り直す | Steam Workshop・Nexus Mods・GitHub を調べ、**ライセンスと対応しているゲームの版**を確かめる。ライセンスが明記されていれば土台にして、足りない分だけ足す |
| 文字列が翻訳ファイルに全部入っていると思い込む | Unreal の locres に入っていない文字列 (アセットに直接ある FText) が数千件あることがある。実機で英語のまま出た画面の文を grep し、**どこから来ているか**を確かめてから「全文」と言う |
| 画像の文字・英語に依存する謎解きに気付くのが遅い | 調査レポートに「訳せないもの」(画像の文字、動画、英語の言葉遊び、英語での入力・検索) の節を必ず作る |

## 2. 表示: 小さく試してから全文へ

| 失敗しかけたこと | 対策 |
|---|---|
| 全文を訳してから、エンジンが日本語を描けないと分かる | **数行 + フォント 1 つ**の試作で、表示・折り返し・フォントの当たり方を先に確かめる。UTF-8 と Shift-JIS の両方を試すと、1 バイト文字しか扱えないエンジンかどうかがすぐ分かる |
| 古いエンジンが Unicode に対応していない | 同じエンジンの新しい版を別の exe として同梱する (AGS)、描画をフックする DLL を足す (独自エンジン) など、元のファイルを書き換えない方法を選ぶ |
| 差し替えたフォントの設定が画面によって効かない | どのフォント設定がどの画面で使われるかの対応表を作る。メニューと字幕で別のフォントのことが多い |
| 字幕が枠からはみ出す・英文の改行が消える | 訳文の行数と長さをビルドのときに数え、超える行を一覧にする。英文の改行 (`\n` `{lb}` `[` など) は訳文でも保つ |
| 選択肢・ボタンが長すぎる | 短い行は別に一覧して手で直す (選択肢は「〜する」の形などに統一)。`%s` の位置は既存の他言語訳が参考になる |
| 検索・入力・名前の判定が英語の文字列に頼っている | 固有名詞は英語のまま残し (用語集で固定)、必要なら日本語の読みを併記する。言語の枠は英語の枠を置き換える |
| 新しいエンジンに載せ替えたら、ゲームのスクリプトが頼っていた古い版の動き (ボタンのマウスオーバー画像の切り替わりなど) が変わり、操作の輪・メニューが反応しなくなる | 載せ替えたら最初に、**主な操作 (調べる・話す・持ち物を使う・セーブ) を一通り**実機で試す。直すときはエンジンの変更履歴から原因の変更を探し、同梱するエンジンだけに小さなパッチを当てる (元の版の sha256 を確かめてから当て、当て直す道具と説明を残す) |
| 書式指定 (`%s`) を足したら、表示が「%s」のまま出る | ゲームのスクリプトが書式の展開を**特定の言語のときだけ**行うことがある。原文に無い `%s` は、ほかの言語の訳にあっても足さない (`gtl review` が手修正でも警告する) |
| 長い文の訳に、文字どおりの `\n` が出る | 改行の書き方はエンジンごとに違う (`[`・`{lb}`・`\r\n`)。訳すときは `\n` にそろえ、書き戻すときにエンジンの書き方へ戻す。訳文に原文に無い `\n` が残っていないかを `gtl warnings` で確かめる |
| 字幕の 3 行目が枠から切れる (行数は英語と同じなのに) | 日本語のフォントは同じ字の大きさでも**行の高さが英語のフォントより高い**ことがある。字幕の枠のフォントの大きさだけを少し下げ (例: 23 → 19)、名前の枠やメニューは変えない。下げた後に、いちばん長い字幕で最後の行の下に余裕があるかを実機で確かめる |
| 訳したらボタンを押しても何も起きなくなった (エラーも出ない) | ゲームが**表示用の文字列を内部の ID・キーとしても使っている**ことがある (表示名から「Tier1」のような ID を組み立てて任務を探す、名前で音声を探す、など)。訳すと照合が外れて、静かに動かなくなる。英語の表示で同じ場面を試して動くなら、訳した文字列が原因と考える |
| 一部の画面だけ日本語が □ になる | 画面によって文字の描き方が違う (Unity では普通の Text と TextMeshPro)。TextMeshPro の代わりのフォントは、決まった字だけを焼いた画像 (中国語の字だけなど) のことがあり、かなが出ない。TextMeshPro を使う画面を探し、日本語の字を含むフォントを代わりのフォントの先頭に足す。足りない字をその都度作る方式は効かないゲームがあったので、**訳文で使う字を起動後にまとめて焼き込む**方式にする (OS のフォントファイルを直接読む) |
| Mod を入れたらゲームが重くなる | 開発用の機能 (英語のまま出た文字列を集めるために、画面の文字を数秒ごとに全部調べる処理など) が動いたままになっていないかを疑う。こうした機能は既定で切っておく |

## 3. 翻訳: 口調のずれ

もっとも多かった問題は、**女性キャラクターの台詞が男言葉になる**こと。翻訳モデルに 1 行ずつ訳させると、
英語には性別が出ないので、「俺」「お前」「あいつ」「〜か？」「〜だろ」「〜だな」「〜ぜ」が混ざる。
あるゲームでは女性キャラクターの台詞の 15〜33% に男性的な言い方が入り、別のゲームでは主要な女性キャラクターの台詞の 1 割弱が男言葉だった。

| 原因 | 対策 |
|---|---|
| 話者が分からないまま訳している | 話者を割り当て (`context.speaker`)、キャラクター表 (`characters.yaml`) を翻訳の指示に渡す ([CHARACTERS.md](CHARACTERS.md)) |
| 話者の割り当てが間違っている (音声ファイルと台詞の対応がずれる) | 割り当ての根拠をデータの行単位で取り直し、数行を原文と見比べる。対応が崩れるデータでは、話者を空にする (中立の口調) ほうがまし |
| 前の行の文脈 (`-history`) に別の話者の口調が入り、引きずられる | 話者が交互に出る会話では文脈を減らす (`-history 0`) か、話者ごとに訳す |
| 1 行ずつの機械翻訳では、キャラクター表を渡しても直りきらない | **ストーリー・会話はエージェント (Claude) がシーン単位で直接訳す** ([TRANSLATION.md](TRANSLATION.md))。前後を読んで訳すので、口調・呼び方・指示語 (「彼女」が誰か) がそろう。UI・アイテム名・大量の説明文は翻訳モデル + 自動チェックで十分 |
| 確認の仕組みが、表に書いた言い方しか拾わない (「あいつ」「満足か？」が素通りした) | 既に訳した分は `gtl speakers-check -masculine` で、表に書いていない男言葉も点検する。乱暴な口調のキャラクターは表の `allow` で許す |
| 性別だけで口調を決めて、キャラクターらしさが消える | 口調はキャラクター表で人物ごとに決める。勝気・荒っぽい女性は「あたし」「あんた」「〜だろ」を使ってよいが、「俺」「〜ぜ」は使わない、のように線を引いて `allow` に書く |

### 確認の誤検知

短い語の部分一致は誤検知が多い。次のものは確認に使わない、または条件を付けている。

- 一人称の「わし」(「出くわし」「そわそわし」)・「私」(「私立」)
- 語尾の「ぞ」「ぜ」(「どうぞ」「なぜ」)。文の終わりだけで見る
- 「〜か？」は、丁寧形 (ですか・ますか・でしょうか)、疑問詞 (何か・誰か)、感嘆 (どれだけ〜か) を外す
- 「あいつ」は「そこ + いつも」を外す
- 二人称の「君」は、名前に付く「〜君」と「諸君」を外す

新しい言い方を確認に足したら、**人が直した後の訳 (正しい訳) で誤検知が出ないこと**をテストで確かめる。

## 4. 翻訳: 機械翻訳の直訳・取り違え

翻訳モデル (PLaMo など) の訳を 5 本のゲームで見直したところ、直した行の多くは **UI の短い語・固有名詞・慣用句** だった。
1 行ずつ文脈なしで訳すので、短い語ほど意味を取り違える。

| よくある間違い | 例 | 対策 |
|---|---|---|
| 多義語の取り違え (とくに UI のボタン・動詞) | `RESUME` →「履歴書」(再開)、`EXIT SCENE` →「脱出シーン」(シーンを終了)、`Show %s` →「%sを表示」(見せる) | 抽出のときに `context.kind: ui` と、画面・用途の説明 (`context.note`: 「ポーズメニューのボタン」など) を付ける。よく出る UI の語は全文翻訳の前に用語集で決める。訳した後、短い UI の行はエージェントがまとめて見直す |
| カタカナに書き写しただけ | 戦闘開始ボタンの `DEPLOY` →「デプロイ」(出撃)、船の種類の名前をそのまま音写 (漂流貨物船など、意味で訳す語) | 見直しで「カタカナだけの訳」を拾う。固有名詞でない語は意味で訳す |
| 人名・地名が普通の語として訳される・訳がぶれる | 普通の英単語と同じ人名 (`Hope` など) が「希望」と訳される、造語の名前に漢字を当てて意訳される、同じ人物の名前が意訳と音写の 2 通りになる | 全文翻訳の前に `gtl consistency` の「固有名詞の候補」を見て、人名・地名・艦名を用語集に入れる (英語のまま残す語も) |
| 同じ語が場所によって違う訳 | 同じ `Defend` が「防御」と「防衛」、主人公の肩書き `Captain` が「船長」「艦長」「キャプテン」の 3 通り | 訳した後に `gtl consistency` で、同じ原文に違う訳が付いている組を一覧して統一する |
| 人物への呼びかけ・敬称が立場と合わない | 女王格の人物への `my lady` が「お嬢様」になる (名前 +「様」や「陛下」が合う) | キャラクター表に、ほかの人物からの呼ばれ方 (陛下・船長など) も書く |
| 慣用句・皮肉・呼びかけの直訳 | 呼びかけの `dear` を「親愛なる」、皮肉を字義どおりに訳す | 会話はエージェントが前後を読んで訳す ([TRANSLATION.md](TRANSLATION.md)) |
| 有名な作品・標語のもじりに気付かない | 映画の題名や標語をもじった台詞を普通の文として訳す | エージェントの見直しで拾う。日本で知られた言い回しがあればそれに寄せる |

**翻訳モデルの訳は、全文翻訳の後に必ず一度見直す。** 見直しは「UI の短い行」「カタカナだけの訳」「`gtl consistency` の結果」の順に見ると効率がよい。
直した訳は `fixes.tsv` に入れて `gtl review` で取り込む (書式記号のずれは手修正でも警告される)。

## 5. 訳文のそのほか

- 人名・地名・団体名を英語のまま残す方針のゲームでは、「`JAKE!` → `Jake！`」が「未翻訳に見える」警告になる。方針どおりなら無視してよい
- 用語集に固定した語 (英語のまま残す固有名詞) は、エージェントが訳した行でも用語集どおりか確かめる
- 成人向けの表現・卑語の多いゲームは、機械翻訳の誤訳 (婉曲な言い方を取り違える) が目立つ。会話はエージェントが訳す
- 人が確認した行 (`fixes.tsv`) は、訳し直しでも上書きしない
- **内部の ID・キーとして使われる文字列は訳さない。** 訳す前に、短い英語の文字列 (`Tier1`・人名・音声の名前など) がスクリプト・データの中で照合や組み立てに使われていないかを grep で調べ、
  使われているものは用語集で英語のまま固定するか、抽出の段階で翻訳の対象から外す。訳した後に動かなくなった操作があれば、まずこれを疑う
- 訳文を gtl の外 (ゲームごとのスクリプト・JSON の修正ファイルなど) で直すと、自動チェックを通らない。直した訳は `fixes.tsv` に入れて `gtl review` で取り込むか、取り込んだ後に `gtl recheck` をかける

## 6. 導入と確認

- ゲームフォルダに書き込む前に、何を入れて何を退避するかをユーザーに見せて確認を取る (`gtl install` は退避と記録をする)
- 外すときの手順 (`gtl uninstall`、消すファイル、Steam の整合性確認) を最初に書いておく
- 新しいエンジンを同梱する方式では、Steam 実績や画像フォントのプラグインが動かないことがある。ゲームが止まらないかを確かめ、説明書に書く
- 実機で通して確かめてもらうまで「完成」と言わない。確かめてほしい画面 (字幕・選択肢・メニュー・長い台詞) を具体的に伝える
- **入れる Mod は、いつも最新の訳文から組み立て直したもの (`dist/<game>`) にする。** 手で作った一式や古いフォルダを別に持っていると、
  インストールの道具がそちらを入れてしまい、古いエンジン・古い訳文に戻ってゲームが止まることがある。
  Mod 一式は 1 か所 (ビルドの出力) だけに置き、入れる前と入れた後に主なファイルの sha256 を確かめて記録する
  訳を直したら、翻訳ファイルだけでなく、同梱するエンジン・フォントを含めた一式を作り直してから入れる
