# これまでの失敗と対策

いくつかのゲームを日本語化して分かった、つまずきやすい点と対策をまとめる。エンジンごとの方法は [ENGINES.md](ENGINES.md)、
口調をそろえる仕組みは [CHARACTERS.md](CHARACTERS.md)、翻訳エンジンの使い分けは [TRANSLATION.md](TRANSLATION.md)。
新しいゲームに取りかかる前と、全文翻訳の後に読み直す。

## 1. 調査: 作る前に「もうあるもの」を探す

| 失敗しかけたこと | 対策 |
|---|---|
| 翻訳を作り始めてから、データの中に家庭用版の公式日本語訳が眠っていると分かる | テキストの表を見つけたら、**まず全部の言語の列を数える**。英語以外の列・使っていない言語の番号・`*_JP` のフォントやスプラッシュ画像を探す。設定ファイルの言語番号を変えるだけで済む場合もある |
| 公式訳はあるがフォントに日本語が無い | 公式訳を英語の枠に入れ、使っている字だけのビットマップフォント (BMFont など) を作る。似たゲームのフォントを流用するときは、**使う字のうち何字が足りないか**を先に数える (3 分の 1 足りないこともある) |
| 既存のファン翻訳を見落として作り直す | Steam Workshop・Nexus Mods・GitHub を調べ、**ライセンスと対応しているゲームの版**を確かめる。ライセンスが明記されていれば土台にして、足りない分だけ足す |
| 文字列が翻訳ファイルに全部入っていると思い込む | Unreal の locres に入っていない文字列 (アセットに直接ある FText) が数千件あることがある。実機で英語のまま出た画面の文を grep し、**どこから来ているか**を確かめてから「全文」と言う |
| 画像の文字・英語に依存する謎解きに気付くのが遅い | 調査レポートに「訳せないもの」(画像の文字、動画、英語の言葉遊び、英語での入力・検索) の節を必ず作る |

## 2. 表示: 小さく試してから全文へ

| 失敗しかけたこと | 対策 |
|---|---|
| 全文を訳してから、エンジンが日本語を描けないと分かる | **数行 + フォント 1 つ**の試作で、表示・折り返し・フォントの当たり方を先に確かめる。UTF-8 と Shift-JIS の両方を試すと、1 バイト文字しか扱えないエンジンかどうかがすぐ分かる |
| 古いエンジンが Unicode に対応していない | 同じエンジンの新しい版を別の exe として同梱する (AGS)、描画をフックする DLL を足す (独自エンジン) など、元のファイルを書き換えない方法を選ぶ |
| 差し替えたフォントの設定が画面によって効かない | どのフォント設定がどの画面で使われるかの対応表を作る。メニューと字幕で別のフォントのことが多い |
| 字幕が枠からはみ出す・英文の改行が消える | 訳文の行数と長さをビルドのときに数え、超える行を一覧にする。英文の改行 (`\n` `{lb}` `[` など) は訳文でも保つ |
| 選択肢・ボタンが長すぎる | 短い行は別に一覧して手で直す (選択肢は「〜する」の形などに統一)。`%s` の位置は既存の他言語訳が参考になる |
| 検索・入力・名前の判定が英語の文字列に頼っている | 固有名詞は英語のまま残し (用語集で固定)、必要なら日本語の読みを併記する。言語の枠は英語の枠を置き換える |

## 3. 翻訳: 口調のずれ

もっとも多かった問題は、**女性キャラクターの台詞が男言葉になる**こと。翻訳モデルに 1 行ずつ訳させると、
英語には性別が出ないので、「俺」「お前」「あいつ」「〜か？」「〜だろ」「〜だな」「〜ぜ」が混ざる。
あるゲームでは女性キャラクターの台詞の 15〜33% に男性的な言い方が入り、別のゲームでは主要な女性キャラクターの台詞の 1 割弱が男言葉だった。

| 原因 | 対策 |
|---|---|
| 話者が分からないまま訳している | 話者を割り当て (`context.speaker`)、キャラクター表 (`characters.yaml`) を翻訳の指示に渡す ([CHARACTERS.md](CHARACTERS.md)) |
| 話者の割り当てが間違っている (音声ファイルと台詞の対応がずれる) | 割り当ての根拠をデータの行単位で取り直し、数行を原文と見比べる。対応が崩れるデータでは、話者を空にする (中立の口調) ほうがまし |
| 前の行の文脈 (`-history`) に別の話者の口調が入り、引きずられる | 話者が交互に出る会話では文脈を減らす (`-history 0`) か、話者ごとに訳す |
| 1 行ずつの機械翻訳では、キャラクター表を渡しても直りきらない | **ストーリー・会話はエージェント (Claude) がシーン単位で直接訳す** ([TRANSLATION.md](TRANSLATION.md))。前後を読んで訳すので、口調・呼び方・指示語 (「彼女」が誰か) がそろう。UI・アイテム名・大量の説明文は翻訳モデル + 自動チェックで十分 |
| 確認の仕組みが、表に書いた言い方しか拾わない (「あいつ」「満足か？」が素通りした) | 既に訳した分は `gtl speakers-check -masculine` で、表に書いていない男言葉も点検する。乱暴な口調のキャラクターは表の `allow` で許す |
| 性別だけで口調を決めて、キャラクターらしさが消える | 口調はキャラクター表で人物ごとに決める。勝気・荒っぽい女性は「あたし」「あんた」「〜だろ」を使ってよいが、「俺」「〜ぜ」は使わない、のように線を引いて `allow` に書く |

### 確認の誤検知

短い語の部分一致は誤検知が多い。次のものは確認に使わない、または条件を付けている。

- 一人称の「わし」(「出くわし」「そわそわし」)・「私」(「私立」)
- 語尾の「ぞ」「ぜ」(「どうぞ」「なぜ」)。文の終わりだけで見る
- 「〜か？」は、丁寧形 (ですか・ますか・でしょうか)、疑問詞 (何か・誰か)、感嘆 (どれだけ〜か) を外す
- 「あいつ」は「そこ + いつも」を外す

新しい言い方を確認に足したら、**人が直した後の訳 (正しい訳) で誤検知が出ないこと**をテストで確かめる。

## 4. 訳文のそのほか

- 人名・地名・団体名を英語のまま残す方針のゲームでは、「`JAKE!` → `Jake！`」が「未翻訳に見える」警告になる。方針どおりなら無視してよい
- 用語集に固定した語 (英語のまま残す固有名詞) は、エージェントが訳した行でも用語集どおりか確かめる
- 成人向けの表現・卑語の多いゲームは、機械翻訳の誤訳 (婉曲な言い方を取り違える) が目立つ。会話はエージェントが訳す
- 人が確認した行 (`fixes.tsv`) は、訳し直しでも上書きしない

## 5. 導入と確認

- ゲームフォルダに書き込む前に、何を入れて何を退避するかをユーザーに見せて確認を取る (`gtl install` は退避と記録をする)
- 外すときの手順 (`gtl uninstall`、消すファイル、Steam の整合性確認) を最初に書いておく
- 新しいエンジンを同梱する方式では、Steam 実績や画像フォントのプラグインが動かないことがある。ゲームが止まらないかを確かめ、説明書に書く
- 実機で通して確かめてもらうまで「完成」と言わない。確かめてほしい画面 (字幕・選択肢・メニュー・長い台詞) を具体的に伝える
