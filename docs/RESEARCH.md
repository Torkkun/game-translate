# 新しいゲームの調査手順

対応したことのないゲーム、[ENGINES.md](ENGINES.md) の方法が当てはまらないゲームを調べるときの手順。
主に Claude などのコーディングエージェントが使う前提で書いているが、人が調べるときも同じ。

## 守ること

- **ゲームフォルダは読むだけ。** 調べるためにファイルを開く・コピーする・解析するのはよいが、ゲームフォルダの中で書き換え・移動・削除をしない。
  解析用に取り出したものは `work/<game>/` に置く (git 管理外)
- **ゲームを起動して確かめるのはユーザーに頼む。** エージェントがゲームを起動・操作しない。見てほしい画面と、何が分かればよいかを具体的に伝える
- **やらないこと**: DRM・暗号化の解除 (鍵の抜き出しを含む)、オンライン対戦・アンチチートのあるゲームへの改変、
  公開されていない鍵やツールの入手。これが必要だと分かった時点で調査を止めてユーザーに報告する
- **外から取ってくるもの** (既存のツール、ファン翻訳、フォント) は、出典とライセンスを確かめてから使う。実行するツールはコンテナで動かす
- **区切りごとに報告する。** 手がかりが無いまま長く掘り続けない (目安は下の「やめどき」)

## 1. 全体を見る (数分)

| 見るもの | 方法 | 分かること |
|---|---|---|
| フォルダの構成 | `find <game> -maxdepth 3` で大きいファイル・拡張子を一覧 | エンジン、データの置き場所 |
| 実行ファイル | `strings` でエンジン名・ライブラリ名、PE のインポート (どの DLL を読むか) | エンジン、描画・文字表示の仕組み |
| 既知のエンジンの印 | [ENGINES.md の表](ENGINES.md#まず確かめること) | 既知の方法が使えるか |
| 言語の設定 | ゲーム内の言語メニュー (ユーザーに確認)、設定ファイル (`*.ini`, `*.cfg`, レジストリ) | 借りられる言語の枠があるか |
| 公式の Mod・翻訳の仕組み | ストアのページ、公式 Wiki、ゲームフォルダの `mods` / `localization` | 一番安全な方法が使えるか |
| 話者の手がかり | 台詞データの話者の列、音声ファイル名、会話データのキー ([CHARACTERS.md](CHARACTERS.md#話者の割り当て-ゲーム固有の拡張でやること)) | 口調をそろえられるか |
| 既存の翻訳 | 「<ゲーム名> 日本語化」「<ゲーム名> translation mod」で検索、Nexus Mods・Steam Workshop・GitHub | 土台にできる訳、データ形式の情報、先人のツール |

既知のエンジン・公式の仕組み・既存の翻訳が見つかったら、それに沿って [ENGINES.md](ENGINES.md) の方法で進める。

## 2. テキストを探す

ゲーム画面に出る英文を 1〜2 文 (ユーザーにスクリーンショットをもらうか、ストアの説明から) 用意して探す。

1. **そのまま探す**: `grep -rl --binary-files=text "<英文の一部>" <game>`。UTF-16 も試す (`grep -P` で `S\x00a\x00m\x00` のように)
2. **見つかったら**: その周りを `xxd` で見て、形式を調べる
   - 1 行 1 件の表 (CSV/TSV/JSON/XML/INI) → そのまま読み書きできる
   - 前後に長さ・ID・オフセットらしい数値がある → 独自の表。ヘッダーの magic、件数、オフセット表を探す
   - 同じファイルにほかの言語の訳がある → 言語の枠を借りられる
3. **見つからなかったら**: アーカイブか圧縮の中にある
   - 大きなファイルの先頭 16 バイトの magic を見る (`PK` = zip、`UnityFS`、`GDPC` = Godot、末尾に pak の索引 など)
   - エントロピーが高い (ほぼランダム) なら圧縮か暗号化。zlib (`78 9c`)・lz4・zstd (`28 b5 2f fd`) の印を探し、展開して再検索
   - 既存の展開ツール (QuickBMS のスクリプト、エンジン用の抽出ツール) があるか検索する
   - 暗号化されていて鍵が無いなら、ここで止めて報告 (「守ること」)
4. **画像の文字**: メニューの見出しやロゴは画像のことが多い。差し替えは後回しにし、どこに何枚あるかだけ記録する

## 3. 読み書きを確かめる (試作)

1. `work/<game>/` に取り出したファイルで、読み込み → そのまま書き出し → 元と同じバイト列になる (往復) ことを確かめる。
   ここが通らない形式は、訳を入れると壊れる
2. 数行だけ英文を目立つ文字列 (例 `[JP]テスト`) に変えたファイルを作り、`dist/<game>-trial/` に置く。
   ユーザーに、ゲームフォルダへ入れて表示を確かめてもらう (入れる前に、何を上書きするか・元に戻す方法を伝え、`gtl install` を使う)
3. 確かめること:
   - 文字が出るか (日本語の字があるか、豆腐 □ や ? にならないか) → 出なければフォントの差し替え・追加が要る
   - 改行・折り返し・文字数の上限、書式記号 (`{0}`, `%s`, タグ) の扱い
   - 文字コード (UTF-8 で読めるか、1 バイト文字しか通らないか)

## 4. 方式を選ぶ

上から順に、使えるものを選ぶ (下ほどゲームへの手の入れ方が大きい)。

1. **公式の翻訳 Mod・翻訳ファイルの追加** (ゲームのファイルを触らない)
2. **使っていない言語の枠を借りる** (公式訳・翻訳ファイルの差し替え。外せば元に戻る)
3. **追加データとして読ませる** (優先して読まれるパッチ・pak・override の仕組みがあれば)
4. **プラグイン・スクリプトで表示の直前に差し替える** (Mod ローダーがあるエンジン)
5. **データファイルを書き換える** (`gtl install` が元のファイルを退避する)
6. **描画をフックする** (エンジンが日本語を描けない場合。DLL のプロキシなど)
7. **画面キャプチャ + OCR + 翻訳のオーバーレイ** (テキストを取り出せない場合の最後の手段)

決めるときに見ること: 外せば元に戻るか、ゲームの更新で壊れにくいか、必要な作業量、フォント・文字数の制約。

## 5. 調査レポートを書いてユーザーに確認する

`games/<game>/調査レポート.md` (データ用リポジトリに保存) に、次の形でまとめる。**方式を決めるのはユーザー。** 大きな作業に入る前に確認する。

```markdown
# <ゲーム名> 日本語化 調査レポート

調査日: <日付> / 対象: <ストアと版> (読み取りのみ。ゲームのファイルは変更していない)

## 結論
<できそうか、おすすめの方式、いちばんの課題> (3 行程度)

## 判明したこと
| 項目 | 結果 |
|---|---|
| エンジン | |
| テキスト | 場所・形式・件数・おおよその文字数 |
| 書式記号 | |
| フォント | 日本語の字があるか |
| 言語の枠 | |
| 既存の翻訳 | 出典・ライセンス |
| 画像の文字 | |

## 方式の案
1. <おすすめ> — 手順、外し方、課題
2. <ほかの案>

## 見積もり
翻訳する文字数と時間の目安 (PLaMo なら 1 時間に約 40 万字が目安)、作るもの

## 未確認・ユーザーに確かめてほしいこと
```

## 6. やめどき

次のどれかに当たったら、そこまでの結果をレポートにして報告し、続けるかをユーザーに決めてもらう。

- テキストの場所が、上の 2 の手順をひととおり試しても見つからない
- 暗号化・DRM・アンチチートに当たった
- 往復 (読む → 書く → 同じバイト列) が通らず、原因の見当がつかない
- 作業量が、ゲームの文章量に比べて大きすぎる (ほかの方式や OCR のほうが現実的)

## 7. 対応が決まったら

[CLAUDE.md の「新しいゲームに対応する流れ」](../CLAUDE.md#新しいゲームに対応する流れ) の 2 (抽出) 以降に進む。
新しく分かったエンジンの一般的な方法は [ENGINES.md](ENGINES.md) に、ゲーム固有の詳細は調査レポートに書く。
